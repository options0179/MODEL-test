# 변경 결과 출력

코드 또는 설정을 변경한 작업의 최종 응답을 실제 변경 내용과 검증 결과에 맞춰 작성한다. 추측하거나 수행하지 않은 작업을 완료한 것처럼 표현하지 않는다.

## 필수 출력 형식

항상 다음 순서와 제목을 사용한다.

```markdown
## 한 일
- 실제로 완료한 변경

## 하지 않은 일 (그 이유)
- 수행하지 않은 항목과 구체적인 이유

## 실패한 일 (그 이유)
- 시도했지만 실패한 작업과 확인된 실패 원인

## 검증 결과
- 실행한 검증과 결과
```

## 작성 규칙

- `한 일`에는 변경된 파일·영역과 실제 완료된 동작만 적는다.
- `하지 않은 일 (그 이유)`에는 사용자가 요청했지만 수행하지 않은 작업, 범위를 벗어나 생략한 작업, 실행하지 못한 검증을 이유와 함께 적는다.
- `실패한 일 (그 이유)`에는 실제로 시도했지만 실패한 작업만 적고, 확인된 오류·원인·재시도 결과를 구분한다.
- 실패한 작업이 없으면 `없음`이라고 적는다.
- 해당 항목이 없으면 `없음`이라고 적는다.
- `검증 결과`에는 실행한 명령이나 확인 방법과 성공·실패를 구분한다.
- 테스트를 실행하지 않았다면 숨기지 말고 실행하지 않은 이유를 적는다.
- 코드 변경이 없는 문서 작업이라도 이 스킬이 호출되었다면 동일 형식을 유지한다.
